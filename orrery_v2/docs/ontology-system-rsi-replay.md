# RSI：真实候选与隔离任务实验

本阶段把系统级改进底座接到模型生成、实际源码执行和独立任务验收。实现位于 `internal/app/improvement`，入口为主机运维命令 `cmd/rsictl`。生命周期复用第一阶段的 Case、租约、不可变修订和 Ontology outbox。

它处理经过明确准入的一项任务实验，不会自动重放任意生产任务。任务准入必须提供完整源码快照、允许修改的资源和版本、实际任务驱动、输入与验收输出、隔离策略及预算。缺少依赖、业务约束、安全样本或留出样本会拒绝准入。

## 实际运行链路

1. 冻结源文件、任务数据集、评估策略、模型请求身份、生成提示词摘要和执行器二进制摘要。`rsictl` 会核对自身二进制和实际提示词；模型密钥与签名密钥通过环境变量提供，不进入产物或候选容器。
2. 在独立 Docker 容器中执行基线的完整任务输入，保存真正的输出、退出码、时长、容器 ID、输入/源码/策略摘要。至少一项 regression 对照必须通过，才允许调用模型，避免把无效驱动当成业务问题。编译或程序失败是任务失败；缺失镜像、Docker 通信失败和无法清理容器是基础设施错误。
3. 通过现有 Eino ProfileModelFactory 调用真实模型。模型仅看到准入源码、可修改目标和 repair 集失败输入/期望；不会得到 regression、held_out 数据集或评估器权限。
4. 模型返回诊断和完整文件替换。宿主校验目标、路径、大小、冻结版本及实际内容变化；生成候选、回滚源文件产物和统一 ChangeSet。允许一次改动多个不同领域的目标文件。
5. 使用相同镜像、驱动、CPU、内存、时间和输出上限，在新的容器中执行候选任务。源代码以只读方式挂载；容器无网络、无宿主凭据、无 Docker socket，使用非 root 用户并移除 capabilities。仅容器 scratch 临时目录允许写入及执行编译产物。
6. 宿主验收器比较实际 JSON 输出与冻结期望，计算完整样本通过率、逐项退步、留出通过、业务约束和安全约束。候选输出的 score/pass 字段没有评分权限。
7. 执行器签名绑定租户、Case、ChangeSet、两组执行、计划和结果。ReplayVerifier 重新解析全部产物、核对签名与摘要，并独立重算分数；通过后才能记录 tested / evaluated。不符合冻结门槛的结果仍保存，随后进入 rejected。

源码/配置文件可以属于 workflow、skill、tool、business_logic、agent_loop、knowledge、memory、ontology、optimizer 中任意已准入目标。**这表示可对对应代码或文件进行隔离实验，不表示已经实现这些领域的在线修改执行器。** 知识索引、远程工具服务、运行数据库和外部业务系统需要另外实现快照、隔离和领域适配器，不能用文件标签代替。

## 证据与中断

`ontology_improvement_artifacts` 按租户及内容摘要存储不可变 JSON 产物。只有宿主协调器持有 HMAC 签名密钥，候选不能自行签署实验结果。签名证明来自受信任执行器，不能防御已经控制宿主、签名密钥或协调器代码的攻击者。

`ontology_improvement_replay_work` 在每个外部操作之前预留阶段，并在当前租约和 revision 仍有效时提交结果。已完成阶段可复用，不能修改实验输入后沿用旧凭据。若进程在发出请求和保存凭据之间死亡，会留下结果未知的预留记录；系统拒绝自动重复该阶段，需运维核查并明确建立新实验。当前尚无自动化的未知操作恢复/补偿流程。

生成模型只接收本轮准入源码、当前摘要和 repair 失败，不会把历年 Case、旧诊断或所有历史记忆自动注入上下文。历史回合保留为证据关联；持久化证据的容量和保留策略仍需后续实现。

预算单位是 `bounded_operations`：冻结的模型调用单位加两组任务执行单位。它限制调用与执行次数，**不是 token 或人民币/美元账单核算**；还需要接入供应商计费与真实 token 预算。容器有实际 CPU/内存/时间限制，模型调用有超时。

## 主机入口

```sh
# 先在受控主机预载镜像，spec.policy.image 必须使用完整 sha256 image ID。
# 先构建 rsictl 并冻结其 SHA256，写入 spec.executor_sha256。
# 密钥只通过受保护环境注入；签名密钥必须是 >=32 字节随机值的 base64。
rsictl --spec /project/artifacts/frozen-task.json \
  --db file:///project/artifacts/experiment.db \
  --work-root /project/.tmp
```

所需环境变量：`ORRERY_RSI_SEAL_KEY`、`ORRERY_RSI_MODEL_URL`、`ORRERY_RSI_MODEL_API_KEY`；数据库也可以通过 `ORRERY_RSI_DB_URL` 提供。签名密钥应保留在受保护的主机密钥存储中，供后续验签使用。

本地 Windows Orrery 的所有命令、数据库、实验文件和临时目录仍必须放在 D 盘。实际容器执行应使用有可用 Docker daemon 的主机；宿主路径必须能被该 daemon 挂载。

## 验收边界

独立验收采用精确 JSON 任务契约，适合有明确输入/输出的任务。它不能替代开放式业务质量评估、统计显著性测试或完整 Agent 任务回放。留出样本通过只说明这些样本通过，不能推导所有输入都正确。

当前 rsictl 使用独立实验数据库完成显式准入实验。与生产任务事件自动归因、准入队列及后台 worker 的连接尚未完成；生产观察仍不会自行生成候选。Case 和各阶段继续具有第一阶段 Ontology 投影能力，独立实验数据库的 outbox 不会自行写入生产图谱。

达到门槛的 Case 停在 evaluated。ReplayVerifier 明确拒绝 monitoring、verified 和 rolled_back；采用、线上反馈与回滚必须由真实领域动作和独立凭据完成。本阶段没有自动发布、没有修改当前服务器运行机制，也没有实现优化器 O0/O1 的公平比较与下一轮自举。
