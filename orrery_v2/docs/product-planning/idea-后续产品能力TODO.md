# TODO: 后续产品能力规划

本文记录当前暂不进入本轮实现、但需要纳入后续产品路线的能力。每一项后续开工前都应补齐目标用户、权限边界、数据模型、API 契约、前端入口和验收用例。

## 待规划能力

- [ ] 工作环境沙箱：为 Agent、工具调用、脚本执行和文件写入提供隔离工作区、权限边界、资源配额、审计日志和清理策略。
- [ ] 功能个人助理：面向个人用户提供常驻助理入口，支持偏好记忆、待办整理、任务提醒、资料检索和跨 Mission 的上下文协助。
- [ ] 审批流规划与角色身份分配：统一建模审批节点、审批角色、代理审批、多人会签、升级规则和审批权限来源，支持按组织、任务、风险等级动态分配审批身份。
- [ ] 人员参与任务视图：明确人员在 Mission / Task / Squad 中的参与状态、职责、贡献、待办、审批责任和退出后的可见性。
- [ ] 首页资源统计：在首页汇总人员、Agent、技能、工具、MCP、知识库、记忆、运行队列、审批和任务等资源状态，提供可下钻的运营概览。
- [ ] 权限管理增强：补齐角色、能力、资源授权、任务上下文权限、临时授权、权限审计和权限变更影响分析。
- [ ] 自动化：支持一次性和周期性任务、提醒、监控、自动巡检、定期汇总和失败重试，并纳入权限与审计体系。

## 后续拆解要求

- 每个能力进入实现前，先补一份独立 spec 或 plan。
- 涉及审批、权限、人员身份和沙箱的能力必须先定义 ActorRef、ResourceRef、PermissionScope 和 AuditEvent 的边界。
- 涉及自动执行或自动化任务的能力必须使用平台 execution / queue / liveness 能力，不新增临时队列。
- 涉及首页统计的能力必须优先复用现有投影和 query service，避免前端拼接多个不稳定接口。
