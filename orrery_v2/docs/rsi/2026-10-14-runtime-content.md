# RSI 第一批实现：评估内容与运行内容一致

这批修改修复一个已经复现的前提错误：先前登记或晋级 v2 后，`load_skill` 仍可能从可编辑目录加载 v1 正文；直接改动目录也能在定义哈希不变时改变运行内容。现在候选的正文、脚本与资源保存为完整包快照，运行请求绑定具体版本和包摘要，加载时逐文件验证大小与 SHA-256。

## 保存与加载

- 快照保存在现有 PackageStore 的 `.versions/<manifest digest>/files/` 下，没有新增数据库。清单随 SkillDefinition 保存在现有定义及版本记录中，DefinitionHash 同时覆盖清单。
- 清单对排序后的路径、文件大小和文件哈希计算摘要。快照先写临时目录，再发布到摘要目录；相同内容可以复用，已有快照不会被覆盖或自动修复。文件不存在或校验失败均返回错误。
- 候选继承基线快照中的资源，再应用 PromptAssets 的修改。没有传入清单的候选也继承已登记的基线，避免悄悄纳入可编辑目录的未评估修改。仍可通过显式继承清单和资源内容创建分支。
- SKILL.md 中的名称、版本、工具声明等字段与定义同步；未知 frontmatter 字段保留。正文会沿用现有 Markdown 生成器的规范化规则，评估器收到的是规范化后重新读取的持久化候选。
- Agent 装配和运行请求复制保留 PackageDigest。`load_skill`、`list_skill_resources`、`load_resource` 使用同一个绑定版本和快照；缺少版本、摘要不符或文件被改动时，拒绝加载。
- 正常晋级和回滚只改变 active 定义，已经绑定的旧运行仍使用旧包。新包的摘要随加载结果返回，可以核验实际加载的内容身份。

生产装配在接受请求前为缺少快照的 active 定义补建快照和版本历史；已迁移定义重复启动不会重新读取可编辑目录。迁移使用启动上下文，失败会阻止启动。部署前必须在生产数据副本上确认全部现有包均可迁移，并同时备份数据库与包目录。

## 验证范围

回归测试覆盖两个真实注册表实现、基线与候选不同正文及资源、发布前加载候选、晋级后的旧运行、回滚、目录改动、文件缺失、篡改、摘要错配、不可见候选、包大小限制、取消、并发重复快照发布、未知 frontmatter 保留，以及文件数据库关闭再打开后的内容与回滚。

应用层测试使用真实 PlatformRegistry、PackageStore、RuntimeToolService 和现有单轮编排，检查评估器读取的候选与最终生效内容一致。该测试的生成器和评分器是测试夹具，只验证接线；不能作为模型生成改进、实际能力提升或递归改进的证据。

验证命令与最终结果保存在本次实施交付说明中。Go 代码经过 gofmt；HTTP 公共请求和 DTO 未增加字段，因此本批没有改动 OpenAPI 或前端生成类型。

## 仍需实现的内容

第一批完成执行内容的一致性基础；发布事务与审计工作已在[第二批说明](2026-10-14-publication-consistency.md)中补齐。整个 RSI 仍未完成：

1. 第二批把 active、版本历史、激活历史与审计事件放入同一事务，并使用完整内容哈希与数据库条件更新拒绝过期发布；独立注册表首次晋级也会保存旧安装基线。审计中心采用可重试转存，历史遗留的错误激活记录仍需单独审查。
2. 旧兼容编辑接口允许同版本更新。绑定摘要会阻止旧运行误用新内容，但这种更新可能令旧绑定无法继续加载；后续应把正式版本视为不可变，并为编辑创建新版本。
3. 单包文件数和大小有上限；快照历史没有整体存储配额或垃圾回收。长期运行前需按 active、运行绑定、评估与回滚引用实施保留和回收策略。
4. PromptAssets 的空字符串沿用现有“从包中读取”语义，本批没有加入资源删除协议。二进制资源保持原有加载预览限制。
5. 快照覆盖包内脚本的字节，不会自动执行它们，也没有冻结外部工具实现、基础模型或服务端 Go 二进制。源码修改与构建发布需要另一个隔离执行边界。
6. 真实候选生成器、基线/候选对照执行器、独立评估产物、底层事件反馈，以及改进器自身的版本化和同预算对照实验仍是下一阶段。

本批代码保存在专用 feature 分支，尚未部署或替换生产服务。
