# WEB/API 任务通知页面适配（2026-10-18）

在私有开源候选分支接入 `/notifications`：阅读 Agent 公开报告、标为已读、下载受授权附件，管理自己的任务订阅和外部渠道偏好。侧栏提供独立入口，普通已认证成员无需 Todo、调度或审批读取权限；这些业务页面的权限要求保持原样。管理页仅向具有 `scheduler.write` 或 `operations.manage` 的用户开放，实际权限仍由后端检查。

页面源自本仓库固定提交 `d3ecba37888b28b8c9c36bece8542c445a46eeb2` 的通知组件和 API 客户端，按候选分支已接入的通知后端适配。没有整体迁入生产工作中心、改动客户端或新增第三方依赖。既有设置页的通知规则是独立功能。

## 本轮修正

- 查询缓存同时包含安全上下文版本、操作者、查看者类型、个人身份与权限范围。账号或权限变化时重新创建页面，清空已选报告、偏好、订阅及管理草稿，取消旧请求；迟到的报告响应不能继续标为已读或显示给新账号。
- 报告正文使用 Svelte 文本转义，不执行嵌入的 HTML；显示执行 Agent 作者和业务状态。站内已读、待发送、等待重试与实际送达分别展示，不把部分完成升级为成功。
- 只有已读写入成功后才显示已读；失败保留未读并提供重试。偏好加载失败时禁止保存；绑定读取失败不冒称尚未绑定。订阅只影响未来结果，不触发业务重跑。
- 组织规则提交保留 revision，冲突时保留草稿并显示错误，允许丢弃修改并重载。成员读取失败时阻止保存。候选任务以来源 ID 选择，避免不同来源的同名 task ID 混淆。
- 修正“失败但没有报告也会通知”的旧文案；接收失败结果仍要求存在 Agent 公开报告。规则保存与接收范围预览分别操作，避免保存成功、预览失败时误报保存失败。
- 管理页明确显示任务和成员加载状态，修复查询完成后保存按钮仍停留在等待状态的问题。
