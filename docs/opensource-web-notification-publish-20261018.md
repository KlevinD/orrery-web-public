# WEB/API 任务通知发布适配（2026-10-18）

本轮在私有开源候选分支补齐任务通知后端，把执行 Agent 的独立公开报告接到站内收件箱、订阅和渠道投递队列。来源为本仓库生产基线 `d3ecba37888b28b8c9c36bece8542c445a46eeb2` 的通知模块，按当前候选分支的自研报告链适配，没有整体合入生产分支。没有引入新的第三方依赖。

## 实际行为

- 管理员可发布本组织 Agent 任务的通知来源，配置订阅、全员或指定人员接收；跨组织来源必须先由可信内部系统建立授权。普通用户只能管理自己的订阅、偏好和已读状态。
- 启用通知后仅处理之后创建的已结束任务。来源采用版本号防止覆盖更新；事件、各接收人的站内通知和渠道记录在同一事务提交，失败回滚后可以重试。
- 只发布身份与执行一致的 `AgentReport`，不把内部 `Summary` 当公开报告。不安全正文直接暂缓发布，保留 `unsafe_agent_report`、`missing_agent_report` 或 `invalid_report_identity` 诊断原因，不在诊断表保存正文或密钥。
- 通知和私助转发共用正文隐私策略，发送前重新核对正文、接收人资格、来源、渠道及接收失败通知的偏好。正文不加平台标题、不补造结论；队列状态与实际投递回执分开。
- 配置了私助结果转发的接收人，在该配置的启用时间或显式重放范围内，微信由私助统一转发。站内通知和允许的飞书通知保留；未配置、启用时间之前或后台任务关闭时，不占用通知模块的微信出口。
- 报告附件只引用 scheduler 已提交且可验证的快照，排除 `blocked-report.md`。下载按当前接收权限和实际来源组织检查，以附件方式返回。

## 代码与契约

后端模块位于 `orrery_v2/internal/app/notification/`，生产接线位于 `cmd/server/production_task_notifications.go`。共享渠道验证器使用追加组合，保留原审批与私助验证器。HTTP 自助路由仍要求已认证身份，管理操作在服务层检查管理权限；请求限制大小并拒绝未知字段和多段 JSON，响应禁止缓存。

OpenAPI 增加 14 条路径、18 个操作，前端 API 类型由锁文件中的 `openapi-typescript 7.13.0` 完整生成。旧生成文件与旧 schema 已存在差异，因此完整生成的 Git 差异较大；同一工具对修改前后 schema 的生成差异只有 1,479 行新增，当前生成结果再次生成后逐字节一致。没有修改依赖锁文件。

## 验证与边界

手工验证包括普通用户管理权限提升拒绝、组织隔离、可信系统跨组织授权、指定接收人撤权、分页/已读隔离、未来运行筛选、缺失/不安全报告暂缓、持久化正文篡改拒绝、事务回滚恢复、文件数据库关闭重开、渠道独立重试，以及真实生产接线中的启用时间/重放/私助去重。网关集成测试使用进程内记录型 sender；生产接线测试的 sender 被调用即 panic，没有实际对外发送。

Windows 定向检查 90 项通过；前端类型检查零错误、零警告，相关契约测试 8 项通过。Linux 完整相关包和源码包/凭据/清单检查的最终结果保存在私有审查目录 `notification-publish-review-20261018`。测试计数包含子测试。一次新增测试因两个场景复用同名内存数据库失败，拆成独立子测试后重跑通过，失败记录保留。追加修复了失败通知入队后关闭接收偏好仍可能继续发送的问题。初次 Linux 检查还发现 main.go 超过现有 800 行结构门禁一行；将启动接线收回已有通知组件后重跑，门禁未修改。

本轮补齐后端及 API 契约，尚未整合生产基线的通知页面。没有证明全库 `go test ./...`、race、多进程/PostgreSQL 并发或真实渠道端到端行为。来源停用阻止后续外发，已有站内历史仍可读；从指定人员范围移除会撤销该历史访问。停用期间恢复、通知留存和清理策略仍需单独评估。

生产基线来自本地固定文档：rev6 记录于 2026-10-18 14:18:35 生效。本轮未重新连接线上，不能把这些测试作为当前线上验收。
