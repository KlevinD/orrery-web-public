# WEB/API 补写报告组织通知与来源校验（2026-10-18）

独立报告现在可以进入组织通知收件箱及既有渠道队列。原业务报告优先；只有原业务记录缺失报告时，才读取已核验的 `scheduled_agent_reports` 正文。通知服务只持有只读报告接口，不激活报告恢复、不调用模型、不续接会话，也不生成替代对话。原报告身份无效时禁止静默改用补写报告。

事件保留原 scheduled run ID、原 Agent 身份与原业务结果，`agent_report.runtime_run_id` 标识实际报告作者，可以是独立补写运行。任务失败不会因为补写成功变成完成；部分结果仍按原有已核验产物规则标识。附件始终从原执行的授权快照读取。JSON 字段、HTTP 路由、Web 页面及生成类型没有修改。

## 来源与接收边界

新增内部 `notification_report_origins` 表，在同一事务内保存原执行摘要和完整通知事件摘要，与事件、收件箱、渠道待发记录共同提交。任何一步失败都会回滚，重试不会产生重复通知。表中不复制原执行私有正文。

首次入队和每次实际发送前，重新读取原执行及报告，核对租户、任务、Agent、原 runtime、终态、完成时间、来源配置/结果、报告作者和原文。更改原执行、补写正文或作者，篡改通知状态/标题，删除来源记录或原执行，都会停止投递。原执行读取失败或报告存储暂时不可用时保留错误，交由既有重试流程处理。投递回执及 trace 可用性变化不会使报告失效。

接收人、组织共享授权、订阅、渠道偏好、失败通知选择和当前规则继续在服务端校验。跨租户结果必须经过现有明确共享规则；独立报告读取使用原租户身份。原私助微信转发仍按启用范围保留，组织通知为同一接收人保留收件箱并处理其他渠道，不重复发送微信。

兼容性变化：缺少新来源记录的旧待发通知停止发送；不从可能已经改变的执行记录补造历史证明，也不自动重放。历史收件箱内容仍按现有共享规则可读。发送门禁拒绝时，Gateway 使用现有 `failed` 状态记录未获准发送；组织推送协调器将不再有资格的记录标为 `cancelled`，两者均不表示已送达。
