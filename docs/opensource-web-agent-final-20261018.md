# WEB/API Agent 终稿事件适配（2026-10-18）

本阶段基点为 `7a1e902d842b9c833234369ccf6eb8cae0d53bc8`，继续准备私有 WEB/API 开源候选。仅适配 F04 的终稿事件与正文保持部分，尚未完成正式公开报告到私助投递的整条生产链。未运行 CI、合并、部署、公开发布或复核线上。

## 修复内容

旧 managed 适配器只转发 message delta 和终态；已有文本时，响应投影不会再从终态补出 final 消息。由此会留下未标记终稿的正文，或只留下工具前进度而丢掉 runner 返回的最终答案。

现在适配器先检查 runner 结果、错误、取消、超时、事件合法性与未完成工具，再为非空的完成结果发送一个 `message_finalized`，随后发送 `turn_result`。流式答案沿用最后一个答案 item ID，使投影以完整正文替换碎片；工具调用前的进度使用独立 item。未流式输出的答案使用当前 generation 的新 item ID。原预算、宿主期限、事件容量、背压关闭和命令幂等保持既有实现。

组合回归另发现自有 HTTP 模型适配器会裁剪正文首尾空白。本阶段去掉该裁剪，保留模型正文中的空格、换行和 Unicode。空内容检查仍使用 TrimSpace，协议字段的规范化继续保留。没有恢复 Eino、AionCore、Multica 或 Redis。

错误、panic、非法结果、未完成工具、超时、取消、超限正文和空拒答均不会被升级成合法终稿。当前候选尚不支持 managed 审批会话；权限事件仍作为不支持的协议事件拒绝，未通过本阶段新增任何授权能力。

## 实际验证

新增终稿回归在旧实现上确定性失败，覆盖有碎片和仅返回最终答案两种路径。生产组合回归使用真实 registry、自有 HTTP 模型适配器、AgentKernel 和文件数据库，检查终稿先于终态、正文与首尾空白保持、响应持久化后仍只有一份 final，模型仅调用一次。模型只连接本地 HTTP fixture；没有调用 Gateway 或消息发送器。

首轮 Windows 组合检查发现上述空白裁剪，修复后的定向检查为 42 项通过、0 失败。Linux 完整 server、runtime、Mission 与 Discussion 检查为 3409 通过、19 跳过、0 失败，退出码 0，共 25 个包通过。测试计数包含子测试；使用 Go 1.25.0、CGO_ENABLED=0，Linux 容器禁用网络。未运行全库 `./...` 或 race。

## 仍需完成的链路

设计基线修订 6 记录的代码为 `1e8e9ad8a691a47d1bc4273a1bdb9dd43f2762cb`；本阶段固定的基线快照记录最终组合的 9 组 Linux 检查已通过、生产激活待回执。这是文档读取证据，不是本阶段线上复核。

当前候选的 `AgentResult` 尚无独立 `UserReport`，scheduler 的 `RunResult` 尚无 `AgentReport`，私助定时结果链仍从 Summary 组织通知正文。因此响应中已有 final，不等于独立公开报告已持久化、已经进入原文投递队列或微信已送达。后续必须整合报告提取、输出安全校验、作者/运行身份、结果持久化与恢复、私助重复扫描幂等及禁止外发的组合回归，不能只补一个字段便宣称 F04 完成。
