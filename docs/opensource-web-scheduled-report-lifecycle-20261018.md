# WEB/API 独立定时报告生命周期审查（2026-10-18）

后续[补写报告组织通知适配](opensource-web-recovered-report-notifications-20261018.md)已补上本文记录的组织通知接线缺口，并增加原执行/通知快照的投递校验。下文保留 `63138c0c85` 阶段的范围与验证记录；RSI、真实 SSE 及报告状态 API/UI 仍待完成。

私有候选接入 `scheduled_agent_reports` 独立报告记录。原执行已有公开终稿时保留原文；缺失时先按租户、Agent、任务、执行 ID 核对原队列和完整终态 trace，再恢复同次执行终稿。确实没有终稿时，由原 Agent 在隔离的 managed runtime 中补写报告。业务执行状态、报告状态和投递状态独立；补写不会重跑任务、改变失败/QA 结果或主动发送消息。

固定自有来源为 `6f7ff475f3d3bb7a2571e881492c76b935ebcaef`（私有 PR 287），候选按实际接口适配。没有新增第三方依赖，也未修改依赖锁、HTTP 契约或客户端。既有第三方声明继续适用。

## 权限与恢复边界

- 仅处理已配置接收人、当前授权有效、在启用范围内的 AgentTask 终态执行；首次启用时间持久保存，重启或指定 replay 都不会补写启用前的历史缺失报告。
- 同一租户/原执行/来源版本独立存储，正文摘要和作者身份在读取及投递重试前复核。来源变化、撤权、正文篡改或旧租约结果会被拒绝。
- 独立 heartbeat 每轮最多启动一次恢复；最多 3 次，间隔 5 分钟，完成后 30 分钟截止，1 分钟租约；CAS 领取和写回隔离过期作者。
- 补写只继承模型绑定和原 Agent 身份，使用全新空工作目录、1 个模型轮次和 18 秒 runtime 限额；外层尝试限额最多 20 秒。工具、技能、MCP、环境、原业务提示词、会话续接、业务任务绑定及 execution envelope 均不传入。
- 队列、trace 和配置中出现身份矛盾、非完整终态 trace、原终稿不符合公开正文策略或缺少明确模型 profile 时停止。明确的 `platform-default` 绑定仍遵循现有平台继承语义；缺失绑定不能静默选择其他 profile。
- 只对 managed 内核开启补写；其他 runtime 缺少终稿时记录内部失败原因。已有可验证终稿的恢复不需要模型调用。
- 投递层只读报告并原文转发，保留候选原有 `ValidateReport`、当前接收权限和幂等校验。入队不代表已投递；补写成功不代表业务成功。

本轮额外回归先验证了不完整 trace、缺失模型绑定和异源 profile 的缺口，再收紧实现。文件库测试真实关闭并重开，检查启用时间、正文、作者及次数保持；真实生产 registry/AgentKernel/工具 journal 配合本地 HTTP 模型 fixture，验证普通回答和恶意工具调用两种路径中业务 dispatcher 调用均为零。测试 sender 禁止实际发送。
