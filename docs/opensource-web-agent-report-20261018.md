# WEB/API Agent 公开报告持久化与私助转发（2026-10-18）

本阶段基于 `4404ad6fc5fc6de6bdfc9d58c293ae9e81a54d98`，继续准备私有 WEB/API 候选。执行 Agent 的公开正文现在独立于内部回执持久化，并能在恢复后原文排入私助投递队列。没有恢复 Eino、AionCore、Multica 或 Redis；没有运行 CI、合并、部署、公开发布或重新检查线上。

## 行为与边界

原候选从 `Summary` 拼接任务状态、时间和固定提示。新增回归确定性复现：只有内部回执、没有 Agent 公开报告的执行仍会进入私助队列。

现在 `AgentResult.UserReport` 只从已完成运行的 final 文本提取，优先采用唯一且闭合的公开区块。区块边界空白会裁剪，机器结果区块另存为内部回执；中间进度、空终稿、多个公开区块、未闭合区块、失败或取消运行均不能提供报告。正文如需输出策略修改才能公开，整份报告扣住，不将删改结果冒充 Agent 原文。

`TaskSubmission` 持久化同一正文；结果恢复沿用既有任务、Agent、运行、幂等键和证据校验。scheduler 的 `RunResult.AgentReport` 保存作者、实际运行 ID 和正文。私助只接受作者及运行身份与当前执行一致、且匹配配置快照的报告，原生维护回执及历史 Summary 不能替代它。

私助持久化正文、来源与材料摘要，材料包含来源租户、执行、状态和报告；重复扫描复用记录，发送前重新检查收件人、权限、租户、绑定账号、终态、激活时间、输出策略、正文及持久化来源。未通过独立 AI 验收的完成报告继续扣住，验收和产物证据门禁未放宽。失败任务若已提交合法的阻塞报告，仍可转发该报告。

新队列使用 v2 幂等键。已送达的 v1 通知映射到同一执行并抑制重发；待发送的 v1 模板无法通过发送校验。没有公开报告时，本链不会生成平台替代话术或再调用模型。旧记录不补造公开报告，激活时间之前的记录仍需显式指定回放。
